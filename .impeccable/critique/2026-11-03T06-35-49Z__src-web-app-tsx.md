## Design Specificity Verdict

**LLM assessment.** Authored, not interchangeable. Matte graphite on obsidian, one warm radial in the top-left, sage as the only action colour, mono micro-labels against Unbounded display and self-hosted Onest body: this reads as the “quiet instrument in a dark room” the product claims, not a SaaS template. The segmented sync bar, the vault row that unfolds into a real diff, and the service hints in Settings are products of *this* repo's constraints. What is not yet specific is the payload: the briefing is a chat transcript pasted into a card, and Needs attention is a database dump with source colours. Both would be improved by the same edit — show fewer, grouped, ranked things.

## Overall Impression

It looks like a place to think, and it is pleasant to open. Then the data arrives: a 923-character briefing wall on top, and a 1453px column of guilt below it that hides a third of the page. The biggest opportunity is not visual polish — it is editorial: the screen should read like a briefing, not like a dump of three databases.

## What's Working

- **A material language that holds.** Iron-bordered graphite cards on a matte obsidian page, one warm light confined to the briefing card and header mark; sage reserved for action and success; every label, count and timestamp in mono with tabular numerals. Nothing glows that shouldn't.
- **Evidence-first interaction.** A vault row expands in place into the actual added line (`+- [[Нацистская оккупация Колпнянского района]]`), and every other row opens its source. The sync bar is per-source, named, and reports its outcome — this is a real “local instrument” behaviour, not a spinner.
- **Settings as the support channel.** Numbered hints per service (OAuth consent in Production, app passwords, token scopes), `Test`, `Copy diagnostics`, the data directory and backup location in plain words. A self-hoster can recover without the README.

## Priority Issues

### [P1] Needs attention is a dump, and it unbalances the page
- **What**: 14 rows, 1453px tall against Activity's 897px, with the same full vault path repeated under 8 consecutive task rows and counts like `90 unread`, `88 awaiting your reply`, `176 more` stacked in one column.
- **Why it matters**: The block is supposed to be “what needs attention now”; instead it is a second inbox with no ranking. Its length beats the briefing for vertical space and leaves a dead half-page under Activity, so the eye lands on the backlog instead of the briefing. Repeating the path eight times also means only ~6 of the 14 items are about distinct things.
- **Fix**: Group by source object (one note row with `×8`, one mail row per sender), cap the list at ~5 with “Show all 14”, and put the path in the row's detail line once, mono and dim. Give the column an explicit end (`All clear` / `Show older`) so it can't grow without bound.
- **Suggested command**: `/impeccable distill`

### [P1] The briefing is a transcript, not a briefing
- **What**: 923 characters, seven raw `-` lines at 17px/1.7 with no list gap and no emphasis; the timestamp sits above the body in the same muted mono as metadata; “Earlier briefings” hangs underneath as a second disclosure.
- **Why it matters**: This is the one thing the user came to read, and it is the least scannable block on the page. Bullets run together (line 1 wraps into line 2 and reads as a paragraph), and the suggestion is buried in the last bullet instead of being marked. The screen's centre of gravity is typographically weaker than the blue links beside it.
- **Fix**: Render the seven bullets as a real `ul` with 8–10px gaps and hanging markers; give the closing suggestion its own treatment (sage left rule, “Suggestion” micro-label); keep one line per idea, truncate with a “Read more”. Move the timestamp to sit with the section label, not above the body.
- **Suggested command**: `/impeccable typeset`

### [P2] The attention links are browser-default blue
- **What**: `.attention a.label` computes to `rgb(158, 158, 255)` with an underline — Chromium's UA link colour for dark `color-scheme`, not `--info` (`#879CB7`) or `--ink`. No global `a` rule exists; every other anchor is styled by a class.
- **Why it matters**: It is the only colour on screen outside the canon, it reads as “unstyled hyperlink” next to a system that is otherwise meticulously toned, and it puts the loudest hue on the lowest-value content (task text). The design doc's link rule (Porcelain → Sage on hover, underline) never reaches these rows.
- **Fix**: Add one rule: `.attention a.label { color: var(--ink); text-decoration: underline; text-decoration-color: var(--line-strong); text-underline-offset: 3px; }` and hover to `var(--accent)`; same for any other bare anchor. Verify with the computed colour, not by eye.
- **Suggested command**: `/impeccable polish`

### [P2] Search suggests with an invalid combobox and a 1088px panel
- **What**: `aria-expanded` sits on a plain `textbox` (axe: `aria-allowed-attr`), the `role="listbox"` options have no `aria-activedescendant` link back to the input, `role="option"` divs are hover/arrow only, and the panel is 1088px wide, covering the briefing's `Briefing now` button and the first lines of the card beneath. The page also has no `main` landmark (axe: `landmark-one-main`), and the input's only label is its placeholder.
- **Why it matters**: Keyboard works, screen readers don't hear the active suggestion or know a list is open; and visually the panel hides the primary action exactly when the user is about to act on a result. At 1534px it leaves ~700px of empty row, which looks like a layout bug.
- **Fix**: `role="combobox"` + `aria-controls` + `aria-activedescendant` on the input, option ids, and an `aria-label="Search notes, mail and Drive"`; cap the suggestion panel at the input width or ~560px and anchor it to the input's left edge. Add `<main>` around the content below the header.
- **Suggested command**: `/impeccable audit`

### [P2] Decorative motion outranks the state it is supposed to report
- **What**: `tilt.ts` tilts `.card` and `.today` up to 1.5° toward the pointer after a 150ms dwell. Cards are not clickable, and text is not in the blocker list, so dragging to select a sentence in the briefing rotates the card under the cursor. Three infinite loops run at once on the dashboard (brand orbit 9s, mark breathe 6s, briefing glow 12s) plus a shimmering sync segment.
- **Why it matters**: On an Operate surface, motion that isn't caused by a state change reads as the interface being nervous. The tilt specifically makes reading and text selection harder and promises an affordance (click/3D) that does not exist; it also conflicts with the design doc's “no 3D, motion reports state”.
- **Fix**: Remove the tilt from `.card` (keep it, if at all, on `.today`), or require a click. Cut the header to one loop (the orbit) and let the glow be static — the doc's ceiling is two infinite motions.
- **Suggested command**: `/impeccable quieter`

## Persona Red Flags

**Alex (power user).** `/`, `b` and Esc work but are documented nowhere on the surface, so he finds them by accident. The attention queue cannot be filtered, collapsed, or bulk-cleared, and “Show 176 more” cannot be undone — the one bulk view he would use is a one-way door. Six service rows each expose 4–5 actions (`Add account`, `Test`, `Edit`, `Reconnect`, `Disconnect`) at identical weight, so the one he wants (`Test`) is a needle.

**Sam (keyboard / screen reader).** The suggestion list is invisible to a screen reader: no `combobox` role, no `aria-activedescendant`, and axe flags `aria-allowed-attr`. There is no `main` landmark, so every tab pass starts in the banner. The Only-label-is-a-placeholder search field loses its name when typed in. Focus rings are present and visible (2px sage) — one thing that is right. Bulk-link reading in Needs attention is underlined, so at least it isn't colour-only.

**Project persona — Marta, self-hoster with a Cyrillic vault.** Her paths are long and mixed script, so every ungrouped repeat of `03 Resources/📜 History & Academia/Нацистская оккупация Колпнянского района.md` costs four wrapped lines; eight of them fill the column. The `03:45 PM` event next to `09:29–15:45` free windows makes her re-read the time twice to be sure it is the same clock. The briefing's content is genuinely hers; the layout makes it feel like a log file.

## Minor Observations

- Times are formatted twice: `toLocaleTimeString([], …)` for events (12h, `03:45 PM`) and `time()` with `en-GB` for everything else (24h).
- `DESIGN.md` is stale: it promises “no web fonts” and “no 3D”, while the build self-hosts Unbounded/Onest and ships a tilt. Future work will follow the wrong contract; the doc needs a pass before the next redesign.
- The browser-only boot splash (1100ms + 380ms) never ships: `isElectron` hides it, so the most elaborate animation in the CSS is dead in the packaged app.
- Settings' Application copy (“Closing the window keeps the app in the tray… Ctrl+Q”) is Electron-only but renders in the browser build too.
- The hint tooltip opens below the `?` and covers the next group's header row at 1534px; it is `position: absolute`, 320px, `left: 0`, so on narrow widths it will clip at the card edge.
- The `TODAY` strip has no calendar status: events appear while no calendar pill exists, so “Calendar not connected” and a populated strip can look contradictory.
- `Show 176 more` renders 176 rows at once with no windowing; with a larger vault this is the one place the 60s refresh could visibly stutter.
- `.detail` is `white-space: nowrap` globally; long add/remove counts survive, but any longer detail string will force horizontal overflow inside the fixed-ratio column.
- Dev-only bug found while running the app: the Vite proxy matches the `/api` prefix, so `/api.ts` is proxied to Fastify and the dev app boots to a blank page with a MIME-type error. `npm run dev` is currently unusable for UI work; the built app is fine. Scope the proxy to `/api/`.
