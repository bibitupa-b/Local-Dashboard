# Local Dashboard 1.16.0

**One screen, one briefing, and now one connection for Microsoft 365.**

1.16.0 adds Microsoft 365 as a single read-only connection: Outlook Calendar events beside the
Google and Apple calendars, and Teams chat mentions as one counted line in the briefing and in
"Start here". Mail, channels and message bodies are not requested.

## Highlights

- **One Microsoft 365 connection** — an Azure app registration with the delegated scopes
  `offline_access User.Read Calendars.Read Chat.Read` yields both Outlook Calendar and Teams chats.
  Paste the Client ID, optionally a client secret, choose the tenant (default `common`), then press
  **Connect**.
- **Outlook Calendar** — events land in the same −1/+7 day window as Google and CalDAV and reuse the
  normal calendar source, so today's events, conflicts and free windows include them. Graph's
  local-time-plus-zone pairs are converted to one UTC instant; cancelled events are marked;
  attendees are kept for meeting signals.
- **Teams chats** — personal and group chats from the last 24 hours, capped at 50 chats. A
  one-to-one chat counts the other person's message as a mention; a group chat counts explicit `@`
  mentions. The result is a single `Teams: N mentions` item and one digest line naming at most five
  chats.
- **Names and counts only** — messages are requested with `$select=id,createdDateTime,from,mentions`,
  so message bodies are never fetched and message text is never stored, logged or sent. The
  `teams_mentions` table holds chat ids and names, senders and times; it is purged with its
  connection.
- **No admin consent for chats** — `Chat.Read` is delegated and granted by the user at sign-in.
  Channel messages would need a tenant-wide permission, so channels are not requested at all. If the
  tenant blocks user consent, an admin approves the four delegated scopes once.
- **Tokens stay encrypted and refresh once** — `offline_access` gives a refresh token, renewed five
  minutes before expiry and saved through `SecretBox`. A 401 refreshes and retries once, a 429
  honours `Retry-After` once. A token without `Chat.Read` leaves the calendar working and Teams
  inert, and one unreadable chat is skipped instead of hiding the rest.
- **Local only covers Microsoft too** — with Local only on, no request reaches
  `login.microsoftonline.com` or `graph.microsoft.com`.

## Install

1. Download `Local-Dashboard-Setup-1.16.0.exe` below and run it.
2. SmartScreen may warn because the build is not code-signed: **More info → Run anyway**.
3. Start the app. Nothing is required; connect a vault, a calendar or Microsoft 365 when you want
   one, and add a DeepSeek key only for the written briefing.

`Local-Dashboard-1.16.0.exe` is the portable build.

Upgrading from 1.15.0 keeps the database and connections. Existing connections keep working; a
Microsoft 365 connection is new and optional.

### Connect Microsoft 365

1. In the Azure portal, create an **App registration** (or reuse one) under **Mobile and desktop
   applications**.
2. Add the redirect URI `http://127.0.0.1:4317/api/oauth/microsoft/callback` (change the port if you
   set `PORT`).
3. Under **API permissions**, add the delegated scopes `offline_access User.Read Calendars.Read
   Chat.Read`. No admin consent is needed: Outlook mail and Teams channels are not requested (if the
   tenant blocks user consent, an admin approves the four scopes once).
4. In **Settings → Connections → Microsoft 365**, paste the Client ID (a client secret is optional),
   keep the tenant at `common`, save, then press **Connect**. Outlook Calendar works with personal
   and work accounts; Teams chats need a work or school account.

## Privacy

The app is read-only toward every service. Microsoft 365 talks only to `login.microsoftonline.com`
for the token and `graph.microsoft.com` for reads. The digest may carry Teams mention counts and
chat names, never message text (message bodies are not fetched); Outlook events carry the same
fields as Google and CalDAV events.
Outlook mail is not requested. Local only blocks all outbound calls, including Microsoft 365,
DeepSeek, weather, RSS, Slack, CalDAV, Gmail, GitHub and Google; only the local vault and browser
history continue. Microsoft tokens and the optional client secret are encrypted with AES-256-GCM.
Otherwise only a compact digest goes to DeepSeek, and only when a briefing is generated. No
telemetry, no analytics.

## Known limits

- **No Teams channels.** Only personal and group chats are read; channel messages need a tenant-wide
  permission and are out of scope.
- **No Outlook mail.** Mail stays with IMAP (Gmail or another account); `Mail.Read` is not requested.
- **No admin consent for chats** — by design, because channels are not requested. If your tenant
  blocks user consent, an administrator must approve the four delegated scopes once.
- **No live Microsoft smoke test** in this release cycle. Verification is unit tests plus
  typecheck/build; a real Azure app registration was not exercised against a tenant here.
- Teams sync reads the last 24 hours and at most 50 chats per run; there is no delta cursor or
  notification stream yet, and a mention older than 24 hours never appears.
- Only personal and group chats are read. Any chat that is not `oneOnOne` is treated as a group
  chat, so meeting chats count explicit `@` mentions only.
- The installer is not code-signed.
- IMAP IDLE and SMTP/Telegram delivery remain in 1.17.0; auto-update, e2e and visual regression are
  Phase 4.
