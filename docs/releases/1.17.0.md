# Local Dashboard 1.17.0

**Mail arrives now, and the briefing can leave on your terms.**

1.17.0 adds two optional paths out of the quiet screen: opt-in IMAP IDLE, which syncs and notifies as
new mail lands in `INBOX`, and opt-in SMTP or Telegram delivery, which sends the saved briefing
after it is generated. Both are off by default; delivery is warned and IDLE is opt-in, and
**Local only** blocks both.

## Highlights

- **Real-time mail, opt-in** — a checkbox on the Gmail connection, **Watch for new mail (IMAP IDLE)**,
  opens one additional read-only connection to `imap.gmail.com` and watches `INBOX`. When mail lands,
  the normal mail sync runs and new mail/reply attention items raise one native notification each.
- **Attention rules decide what notifies** — IDLE does not invent a second inbox. It reuses the
  existing unread/reply items, so only mail the dashboard already counts is announced; a message is
  not announced twice while its id stays in the seen set (persisted in `settings`, bounded to 200).
- **Reconnect, not a hang** — a dropped IDLE connection reconnects after 1 s, 2 s, 4 s and so on,
  capped at five minutes. Overlapping events coalesce into one queued sync through a serial runner,
  and the existing 15-minute polling continues as the fallback.
- **Delivery is a separate, disabled group** — SMTP and Telegram connections send the saved briefing
  after a successful generation. Both default to `enabled: false`; each channel has its own result,
  and a failing channel never blocks the other or the saved briefing.
- **Explicit warning** — the Settings → Connections **Delivery** group says: *The briefing markdown
  leaves this machine. It does not include the digest, though its bullets may quote subjects and
  snippets. It is off until you enable a channel.*
- **Local only covers both** — no mail source is built with Local only on, so no IDLE watcher runs,
  and `deliverBriefing` returns before any send. Vault and browser history keep syncing.

## Install

1. Download `Local-Dashboard-Setup-1.17.0.exe` below and run it.
2. SmartScreen may warn because the build is not code-signed: **More info → Run anyway**.
3. Start the app. Nothing is required; connect a source when you want one, and add a DeepSeek key only
   for the written briefing.

`Local-Dashboard-1.17.0.exe` is the portable build.

Upgrading from 1.16.0 keeps the database, connections and settings. IMAP IDLE and delivery are new
and off; existing Gmail connections keep polling exactly as before until the checkbox is enabled.

### Watch mail with IMAP IDLE

1. Open **Settings → Connections → Gmail** (or add a Gmail connection).
2. Check **Watch for new mail (IMAP IDLE)** and save.
3. When mail arrives in `INBOX`, the app runs the normal mail sync and shows a native notification for
   each new mail or reply item that the attention rules count.

The watcher only opens `INBOX`. Other folders keep syncing on the 15-minute schedule, and polling
continues for `INBOX` too, so a missed IDLE event does not create a permanent gap. The connection uses
the same app password as polling; no new credential is needed. It stays idle in the background and
reconnects on its own after a dropped connection.

**Note:** a notification is only as useful as the attention rules. Promotional or already-read mail
that the rules ignore will sync without a notification, by design.

### Turn on delivery

1. Open **Settings → Connections → Delivery**.
2. Add **Email (SMTP)**: host, port, from, to, username and password. Port 465 uses implicit TLS;
   other ports use StartTLS.
3. Or add **Telegram**: a bot token from @BotFather and the chat id of the conversation to post to.
4. Enable the connection. Delivery stays off until you do.

Read the warning in that group first: **the briefing markdown leaves this machine; it does not include
the digest, though its bullets may quote subjects and snippets.** The email body is the briefing
markdown (headline, bullets and suggestion); the subject is
`Local Dashboard - <headline>`. Telegram receives the same markdown as one message. Each send is
limited to 20 seconds, and SMTP requires STARTTLS on non-465 ports.

A failed send is recorded on the connection in Settings (its lastError dot) and written to the server
log by connection id only — never with the password, bot token or briefing text. The briefing is
still saved locally, and the next source sync or briefing is unaffected.

## Privacy

The app remains read-only toward every source. IMAP IDLE adds one persistent read-only TLS connection
to `imap.gmail.com` and reads `INBOX` headers and bodies exactly like the existing poll; nothing new is
sent to Gmail. Delivery is the second explicit exit from the machine: when, and only when, you enable
an SMTP or Telegram connection, the saved briefing markdown goes to your SMTP server or
`api.telegram.org` — it does not include the digest, though its bullets may quote subjects and
snippets. The digest itself also carries the previous briefing's headline and suggestion. There is
no delivery retry queue and no third-party relay.

Local only blocks DeepSeek, weather, RSS, Slack, Microsoft 365, CalDAV, Gmail, GitHub, Google, IMAP
IDLE and delivery; vault and browser history continue. SMTP credentials and the Telegram bot token are
encrypted with AES-256-GCM in the `connections` table, like every other secret. No telemetry, no
analytics.

## Known limits

- **No live IMAP IDLE smoke test** in this release cycle. Verification is unit tests plus
  typecheck/build; a real Gmail account was not held idle and dropped here. The backoff and dedupe
  logic are covered directly; the socket behaviour is `imapflow`'s.
- **No real SMTP or Telegram smoke test.** Delivery is covered with injected senders and setup-error
  containment; no live SMTP server, mailbox or bot was exercised.
- **The 20-second timeout rejects the delivery promise but does not abort the socket.** A stuck SMTP
  connection or Telegram request is abandoned rather than cancelled; the briefing is still saved.
- **IDLE watches `INBOX` only.** Other mail folders still rely on the 15-minute poll, and IMAP is
  Gmail-only in this app, so IDLE is Gmail-only.
- **The seen set is bounded to 200 message ids.** In an extreme burst, an id that falls out of the
  set while still unread could be announced again.
- **No delivery retry.** A failed channel is recorded on the connection in Settings and logged; the
  next briefing is a fresh send.
- **The installer is not code-signed**, so SmartScreen may ask for confirmation.
- Auto-update, Playwright e2e/visual checks and opt-in signing configuration remain in 1.18.0;
  builds stay unsigned by default.
